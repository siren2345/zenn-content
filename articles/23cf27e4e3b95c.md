# はじめに

RTX 5090 (32GB VRAM) でローカルLLMをコードエージェントとして動かせないか
試行錯誤したメモです。結論から言うと「モデル選び」と「ツール呼び出しの相性」で
かなり振り回されました。同じ轍を踏まないよう残しておきます。

## 環境

- GPU: NVIDIA RTX 5090 (32GB VRAM)
- Ollama: 0.32.15
- モデル: qwen3-coder:30b / qwen3:32b など

## ハマったポイント

### 1. 32GB でも dense モデルでは 256K は非対応

最初 `qwen3:32b`（dense）を試しましたが、256K コンテキストは **非対応**。
Ollama は VRAM に応じてコンテキストを自動制限します（この環境では約 40K）。

**正解は MoE の `qwen3-coder:30b`**（30B total / 3.3B active、ネイティブ 256K、最大 1M 拡張）。
dense の 32B より遥かに速く、大コンテキストを扱えます。

### 2. Claude Code は未認識モデルIDに 65.5K 窓を仮定する

Claude Code はモデルを認識すると本来の窓を使いますが、未認識IDだと
デフォルトの **65.5K** を仮定します。`auto-compact` バッファが 50% を占めるため、
実質使えるのは約 45% 程度でした。

これを解決するには `CLAUDE_CODE_MAX_CONTEXT_TOKENS=262144` で
モデルの正しい窓を宣言する必要があります。`/context` で確認できます。

### 3. `--model` フラグを settings.json が上書きする

`ollama launch claude --model qwen3-coder:30b` と指定しても、
`~/.claude/settings.json` の `ANTHROPIC_MODEL` が**優先**されて `--model` を上書きします。
モデルが切り替わらないときは必ず settings.json を確認しましょう。

### 4. 結局、Claude Code のツール呼び出しはローカルモデルと相性が悪い

256K 窓自体は実現しましたが、`qwen3-coder:30b` は Claude Code の
ツール呼び出しプロトコルを正しく生成できませんでした。
PDFや資料の内容を「実行せよ」と誤読して、勝手に `<function=Write>` を出すなど、
エージェントとして使えるレベルではありませんでした。

- auto-mode をオフにしても、モデル自体が誤読し続けるため解決しない
- ツール呼び出しの形式（JSON tool_calls）とモデルが返す形式（独自XML）が不一致

## 解決策: opencode に切り替える

Claude Code を諦め、**opencode** に切り替えました。
opencode はローカルモデルのツール呼び出し(WebFetch等)が正しく機能します。

`~/.config/opencode/opencode.jsonc` に Ollama プロバイダを定義:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/qwen3-coder:30b",
  "small_model": "ollama/qwen3-coder:30b",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": {
        "baseURL": "http://localhost:11434/v1",
        "apiKey": "ollama"
      },
      "models": {
        "qwen3-coder:30b": {
          "name": "Qwen3-Coder 30B (local)",
          "limit": { "context": 262144, "output": 65536 }
        }
      }
    }
  }
}
```

起動:

```powershell
opencode --model ollama/qwen3-coder:30b
```

## 環境変数まとめ

```powershell
# Ollamaのコンテキスト長(256K)
OLLAMA_CONTEXT_LENGTH=262144
# Claude Codeが仮定する窓
CLAUDE_CODE_MAX_CONTEXT_TOKENS=262144
# 自動圧縮のしきい値
CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000
```

## 教訓

1. 大コンテキストが欲しいなら **MoE モデル** を選ぶ（dense は 256K 非対応）
2. ローカルモデルでエージェントを使うなら **opencode 系** の方が相性が良い
3. Claude Code の設定は settings.json の `ANTHROPIC_MODEL` が最優先
